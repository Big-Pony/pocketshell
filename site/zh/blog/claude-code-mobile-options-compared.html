手机上跑 Claude Code 的所有方案，一次比全

"手机上怎么用 Claude Code"不是一个答案，而是至少六个，解决的是不同的问题。先给一张地图，你可以直接跳到自己需要的那一段，不用从头看到尾。

先问自己一个问题

你需要什么先看哪一段
想要官方、免搭建的路径，不介意订阅要求下文 Cloud sessions 或 Remote Control
想把任务丢给 Desktop，过会儿再回来看结果下文 Dispatch
想要一个专门为 Claude Code 做的自托管 Web 界面下文 CloudCLI（自托管或云端版）
已经有 SSH 能用，只想要个纯终端下文 SSH 客户端 + tmux
想要手机原生触屏键盘、断线重放、推送通知，且要自托管一款自托管、手机原生的终端客户端（下文）

如果上面几条都不太对，接着往下看——对比表后面那三条，讲的是"什么都别自建"更合适的场景。

官方 App：其实是三种不同模式，不是一种

Claude 官方 App 本身不是单一的手机体验，而是三种，用的是哪一种，决定了你的手机实际连的是什么。（来源，官方文档）

Cloud sessions

任务跑在 Anthropic 自己的基础设施上，不是你的笔记本。这是唯一一个电脑可以完全关机的官方选项——开始任务、合上盖子，回头再看结果。

Remote Control

手机驱动的是已经在你自己机器上跑着的 Claude Code（或 Claude Desktop）会话。目前是研究预览版，Pro、Max、Team、Enterprise 都能用，但 Team 和 Enterprise 默认关闭，得由组织所有者手动打开。（来源，官方文档） 因为绑定的是一个正在跑的本地进程，它也继承了这个进程的所有限制：断网大约十分钟以上，会话就会超时、底层进程随之退出；而关掉它所在的终端或编辑器窗口，进程直接就没了——官方文档正是因为这个原因，建议把它放进 tmux 或 screen 里跑。（来源，官方文档）

Dispatch

把任务派给你自己机器上的 Claude Desktop，之后再回来看结果，而不是实时驱动一个正在跑的会话。仅 Pro 和 Max 有，Team、Enterprise 账号没有这个功能。（来源，官方文档）

CloudCLI（claudecodeui）：专门做的自托管 Web 界面

CloudCLI 是一个开源 Web 界面，接到你自己的机器上，AGPL-3.0-or-later 协议，截至今天 13.2k star、1.8k fork。（来源，官方仓库，2026-08-07 复查） 它是本文所在这个自托管 Web 层思路最直接的同类项，而且覆盖范围比单一工具更广——同一个界面下还能驱动 Codex CLI、Cursor CLI 等其他编码 agent。

自托管需要 Node.js v22+，如果想从局域网外访问，还得自己配反向代理做 HTTPS。（来源，官方仓库） 现在也有托管版本：商用的 CloudCLI Cloud 已经上线——README 的 Quick Start 里排在第一位，标着"(Recommended)"，起价 €7/月，FAQ 里写得很直白：合上笔记本，agent 照样继续跑。（来源，官方仓库） 这是任何自托管方案——包括 PocketShell——在定义上都做不到的事：自托管就需要有台机器跑它的 agent。

项目目前有 103 个 open issue，其中两个正是本文接下来要讨论的：一个是 iOS Safari 上聊天的流式响应容易丢（#554）；另一个是 v1.35.1 版本下，iOS 切到后台之后 shell 终端会静默冻结，而聊天区还在照常更新（#953）。（来源，他人报告，我们未复现） （来源，他人报告，我们未复现） 这些是一个活跃项目里正在跟进的 issue，不是给这个工具下"能不能用"的结论——一个年轻且还在积极维护的项目有公开的手机端 bug 报告，是正常状态，不是否决理由。

裸 SSH 客户端 + tmux

如果你已经有一台能 SSH 上去的机器，依赖最少的路径就是用手机 SSH 客户端（Termius、Blink、JuiceSSH）直接连进一个已经跑着 claude 的 tmux 会话。这是这份清单里最灵活的选项——服务器端不用额外装任何东西——但也是最靠手动的：任务跑完不会推送通知，没有为触屏优化过的 Ctrl/Alt/Esc 按键行，会话名字得自己记、断线了得自己重连。

PocketShell 在这张地图上的位置

PocketShell 是一个专门补这个空档的自托管单文件程序：一个为持久终端会话做的手机原生客户端，不是通用 SSH App，也不是 CloudCLI 那种多 agent 仪表盘。你机器上的 tmux 会话才是真身，手机只是一层加密（Noise IK）的薄窗口。断线重连之后只按序号补发你错过的那部分输出，不用自己往回翻。因为整套交互是触屏优先设计的，它内置三种可切换的屏幕键盘布局（经典、分层、Flick），外加一个独立的输入法缓冲区用来先拼好整句再发送；推送方面直接把 Web Push 和外发 Webhook 接到会话完成的钩子上，覆盖 Claude Code、Codex、opencode、Kimi CLI 四个工具——任务跑完是收到通知，不用自己盯着屏幕轮询。

它刻意没做的事：没有云端执行模式，所以和 Cloud sessions 不同，你的机器还是得开着；没有团队/组织权限体系，只有设备配对，是为一个人管自己的几台机器设计的，不是给团队共享部署用的；它是个 PWA，不是从应用商店装的东西。

重新核实过的对比

方案跑在哪机器要开着吗费用值得知道的事
Cloud sessionsAnthropic 的基础设施不用包含在 Pro/Max/Team/Enterprise 里唯一一个电脑可以关机的官方选项
Remote Control你的机器要包含在 Pro/Max/Team/Enterprise 里（Team/Enterprise 默认关）研究预览版；约 10 分钟断网超时；进程随所在终端一起没

CloudCLI 自托管你的机器要免费、开源多 agent 仪表盘；两个已知手机端问题，均未关闭
CloudCLI CloudCloudCLI 的基础设施不用起价 €7/月托管版，笔记本可以合盖——没有自托管方案能做到这点
SSH 客户端 + tmux你的机器要一个 SSH App 的钱，可能你已经有了最灵活也最手动——没有通知，没有触屏键盘
PocketShell你的机器要免费、自托管（Apache-2.0）手机原生键盘 + 重放 + 推送，专职终端客户端

三种情况下，什么都别自建

把这个说清楚，是一篇由方案本身来写的对比文章唯一能建立可信度的方式，所以：

  • 你的电脑有时候要关机。 这页上所有自托管选项——CloudCLI 自托管模式也好、PocketShell 也好——都需要一台开着的机器才能连上。如果计划是"合上笔记本，工作还得继续"，那是 Cloud sessions 或 CloudCLI Cloud 该管的事，不在这份清单里。
  • 你只是偶尔想瞄一眼进度。 如果偶尔看看就是全部需求，官方 Remote Control 已经能做到这点，只要账号订阅层级对，零额外搭建。为了偶尔瞄一眼去搭一个自托管服务，投入和问题不成比例。
  • 你不想维护一个服务。 不管是 CloudCLI 还是 PocketShell，自托管都意味着你得自己让进程一直活着、自己打更新、坏了自己排查。如果这不是你想接受的代价，上面那几个托管选项（Cloud sessions、Dispatch、CloudCLI Cloud）存在的意义就是让你不用做这件事。
