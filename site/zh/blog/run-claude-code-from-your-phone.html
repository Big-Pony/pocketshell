手机上跑 Claude Code：所有路径一图看懂

能——手机上确实可以查看一个正在跑的 Claude Code 任务，甚至直接驱动它。但没有唯一一条"标准答案"路径。这一页是所有真正能用的方案的简要地图，每一条都配一篇更深入的文章链接，想看细节点进去就行。

为什么手机不是天生就能做到这件事

Claude Code 是个命令行工具——它默认下面有一个真正的终端，能读按键、能像 TTY 那样渲染画面。手机默认是不带终端的，所以从"手机"到"Claude Code"之间总要先经过点别的什么：一个连着 Anthropic 服务器或你自己机器的官方 App，一个直连你自己那台机器的 SSH 客户端，或者一个专门做出来夹在中间的 Web 客户端。选哪一层，决定了你实际依赖的是什么。

官方 Claude App

如果你已经有对应订阅层级的 Anthropic 账号，这是门槛最低的起点。它包含两种不同模式：Cloud sessions 把任务跑在 Anthropic 自己的基础设施上，所以你的笔记本可以完全关机；Remote Control 则是驱动一个已经在你自己机器上跑着的 Claude Code 会话，这意味着它多依赖了一层——你机器的在线状态和网络。（来源，官方文档）

Remote Control 目前是研究预览版，而且因为绑定的是一个正在跑的本地进程，它有实实在在的限制：断网大约十分钟以上会话就超时；关掉它所在的终端或编辑器窗口，进程也跟着没了。（来源，官方文档）

CloudCLI（claudecodeui）：专门做的自托管 Web 界面

如果你完全不想依赖 Anthropic 的账号订阅层级，CloudCLI 是一个接到你自己机器上的开源 Web 界面——是这个方向上最成熟的自托管替代品，还在积极维护，而且同一个仪表盘还能驱动 Claude Code 之外的其他编码 agent。现在也有托管版本了，所以"机器必须一直开着"并不是整个 CloudCLI 项目的硬性要求，只是它自托管模式的要求。

详见 → CloudCLI 两个已知的手机端问题，各自的触发条件，以及一个不同架构如何避开同样的失败模式。

纯 SSH 客户端 + tmux

如果你已经有一台能 SSH 上去的机器，这是活动部件最少的方案：手机上一个 SSH App，连进一个已经跑着 claude 的 tmux 会话。这条路是真的能用——进程能扛过断线——但手机该有的那些体验得自己想办法：任务跑完不会推送通知，没有为触屏优化过的 Ctrl/Esc/方向键，网络一有风吹草动就得自己手动重连、重新 attach。

PocketShell 在这张地图上的位置

PocketShell 是一个自托管的单文件程序，专门为了做一个手机原生的终端客户端——不绑定 Anthropic 账号或订阅层级，也不局限于 Claude Code：终端本身是通用的 tmux/PTY 托管，任何你平时用 SSH 跑的命令行工具在这里都能跑，只不过只有四个工具（Claude Code、Codex、opencode、Kimi CLI）能拿到开箱即用的自动完成通知。它内置专门的触屏键盘、基于序号的断线重连重放（不用手动重新 attach），以及 Web Push 加外发 Webhook 的通知。

它不是什么：没有云端执行模式，所以和上面的 SSH 方案一样，你自己的机器仍然得开着；它的界面专门针对手机大小的屏幕，不是为更大的平板或桌面布局做的。
