iPad 上怎么用 Claude Code：三条路径分别是什么体验

短答案：能。长答案：真正能走的有三条完全不同的路，选哪条对体验的影响比"能"这个字暗示的要大得多。

为什么这个问题不能一句话答完

iPadOS 本身不带终端，而 Claude Code 是个命令行 TUI。想让它出现在 iPad 屏幕上，一定要先经过点别的什么——一个 App、一个 SSH 客户端，或者一个连着真正在跑终端的机器的浏览器标签页。

三条路径

1. 官方 Claude App

iPad 上装的是和 iPhone 一样的那个 iOS 版本 App。（来源，官方文档）进去之后用的是 Cloud sessions 或 Remote Control，跟手机上完全一样。如果你已经有对应账号层级，这是门槛最低的一条路——不用另外配 SSH、不用记服务器地址。

2. SSH 客户端 + tmux

Blink、Termius 这类 iPad SSH 客户端直接连你自己那台已经在 tmux 里跑着 claude 的开发机。这条路给你的是真正的终端体验——真实的按键绑定、真实的回滚缓冲，中间没有经过任何移动端 UI 层的转译。

3. 远程桌面 / VNC 连一台真电脑

这条路上你根本没有在 iPad"上"跑 Claude Code——你看到的是一整个通过 VNC 之类协议传过来的桌面，Claude Code 只是上面的一个窗口。能用，但是最重的一条路：延迟更高、流量更大，而且是把一整台电脑的界面硬塞进一块从设计上就不是为它准备的平板屏幕。

每条路各自撞到的墙

路径短板在哪
官方 App跑的还是 iPhone 版本的布局；Remote Control 依旧要求你自己那台电脑保持开机、跑着 Claude Code 或 Claude Desktop——电脑关机的话得换成 Cloud sessions （来源，官方文档）
SSH 客户端会话保活要自己管（可以看我们另一篇讲 SSH 断线怎么办的文章），没有内置推送通知，纯键盘驱动的操作方式——尤其是 Ctrl、Esc 这类修饰键——在没有外接键盘或客户端自带功能行的触屏上不算顺手
VNC / 远程桌面延迟更高、流量更大，你操作的是一整台电脑的界面，而不是专门为触屏设计的东西
有一点值得直说，因为这问题多半就卡在这个细节上：以上所有路径——包括下面这个——都不会把 iPad 变成一个专为平板打造的 IDE。接下来说的是一个"手机形态、也能在平板上打开"的工具，不是"平板原生布局"。

PocketShell 在哪一段有用

PocketShell 是纯 Web 应用（PWA），不用上 App Store。iPad 上打开 Safari，指向你自己的服务器就能用；"添加到主屏幕"能拿到一个看起来像独立应用的图标，不用经过应用商店的审核流程。因为裸终端的触屏输入才是真正的痛点，它做了一整套自定义的屏幕虚拟键盘，专门补上没有外接键盘时会缺的那些键——Ctrl、Alt、Esc、方向键、外加一排功能键；还有一个独立的输入法缓冲子 tab，系统输入法（对中文、表情这类组合输入有用）可以整段发送，不用跟终端逐字符较劲。

直说它不做什么，呼应上面那条提示：它不是针对平板优化过的布局。项目本身的定位就是明确的手机浏览器优先（390×844 级别视口），在 iPad 浏览器里打开，拿到的还是那套手机宽度的界面，不会像原生 iPad App 那样把多出来的屏幕铺开用。如果你要的正是大屏、平板原生的编码体验，这里说的四条路——包括这一条——没有一条是为这个准备的。
